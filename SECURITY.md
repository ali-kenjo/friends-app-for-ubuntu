# Security

Friends is meant to run on your own computer.

- The helper listens on `127.0.0.1` only and refuses requests whose `Host` or `Origin` isn't one of its own addresses (this blocks other websites in your browser from using it). `ALLOWED_HOSTS` adds more, and `*` turns the checks off: only do that behind something you trust.
- **Local API authentication**: Every install generates a random 32-byte session secret stored in your data folder (`session-token`, mode 0600). All API endpoints (`/api/*`), event streams (`/api/events`), and WebSockets (`/api/live`) require an HttpOnly, `SameSite=Strict` cookie (`friends_session`). The desktop and web launchers pass the token via a URL hash fragment (`#token=...`) which the frontend exchanges for the session cookie and immediately clears from the browser history. Requests without a valid session receive `401 Unauthorized`.
- API keys go to the system keyring, or a private file (mode 0600) in your data folder. A key is only sent to the service it belongs to; a local AI's key never falls back to your Gemini key.
- File tools work only inside the folders you allow, follow symbolic links before checking, and ask before acting.
- In Auto, Dynamic and Fastest mode, a message only goes to the cloud after you agree (configurable); declining keeps it local.
- **Private mode** (Settings → AI & privacy → Privacy) keeps everything on the computer: no cloud AI, Google or GitHub, nothing from other websites. Outside Private mode, **Hide from cloud AIs** swaps keys and passwords, card numbers, and (if you switch them on) email addresses and phone numbers for a placeholder before a message goes to a cloud AI, also in what a tool reads out; it is a safety net for the usual shapes of these things, not a guarantee. You can also keep your memories, notes and remembered chats from cloud AIs, and "What could leave this computer now" lists what could send something.
- **Cloud AIs** other than Gemini are reached with the key you gave, only at the service's own address (an `https://` address, with no key inside it); the key is kept in the system keyring and never goes to the page.
- Local voice (`voice/server.py`) listens on `127.0.0.1` only and refuses other `Host` headers.
- **Connected apps** (GitHub, Notion, Todoist, Home Assistant) and **MCP servers**: their tokens go to the system keyring, never into backups or to the page. Actions that change something ask first (Home Assistant: locks, alarms and covers always ask; MCP: each action asks unless you trust that app). On camera (ON AIR) none of your accounts, files or memories are offered to the AI.
- **Reading web pages**: the AI can't open anything on this computer or your home network; the address is checked when connecting and on every redirect, with size and time limits.
- **Missions (Labs)** (what the assistant does for you in the background) run under a strict gate, not on trust: the plan lists every action that sends, deletes or runs a command, and approving it covers exactly those. Anything else pauses the mission and asks you, in the app and on Telegram.
  - **Bubblewrap sandbox**: Every mission command runs inside an isolated Bubblewrap (`bwrap`) container. The command gets a private `/tmp`, fresh unshared `/proc` and `/dev`, minimal read-only system mounts, and no access to your real `$HOME` or `~/.config/friends`.
  - **Network isolation**: The sandbox unshares the network namespace by default. A command cannot access the internet or local network unless the approved plan explicitly declared a step with `{"type":"internet"}`. Shell wildcards never grant network access.
  - **Hard failure mode**: If `bwrap` is missing or unprivileged user namespaces are blocked, commands refuse to run outside the sandbox; the mission pauses cleanly and reports troubleshooting steps.
  - Files stay in the folders you allow and the mission's own folder, deletes go to the trash, commands run with a time limit and a scrubbed environment without your keys, and `sudo`, installs and system settings always ask. Stop works at once. In Private mode a mission never uses the cloud: it pauses instead.
- **Telegram (Labs)**: your own bot, long polling (no open port, no incoming webhooks); its bot token is kept in the system keyring.
  - **Pairing is the only way in**: Automatic admin assignment for the first user has been removed. Pairing via one-time 6-digit codes (`/pair <code>`) generated in the app is required. Codes expire in 10 minutes and are burned after 5 invalid attempts.
  - **Role-based permissions**: Paired users have explicit roles (`admin`, `chat`, `notify_only`). Only admins can approve plans, trigger commands, or manage missions. Unpaired callers in private chats receive a pairing hint; in groups, messages from unpaired users are dropped silently.
  - **Group chat privacy**: In group chats, private data (notes, calendar events, past chats, Google tokens) is withheld by default (`allowPrivate: false`). Each group chat has a dedicated toggle in Settings to allow private data access only if explicitly granted.
- **Reddit connector & prompt-injection defense**: official Reddit Data API integration using pure OAuth 2.0 PKCE with client ID and secret stored in the system keyring. Enforces a strict 100 queries per minute rate limit with header tracking. All community submissions and comments are wrapped in untrusted data delimiters (`<untrusted_reddit_content>`), and posting or commenting actions are placed in the `sends` risk class requiring explicit human confirmation. Completely blocked in Private mode.
- **Whiteboard**: client-side vector board sanitized with DOMPurify, stored locally as JSON in your data folder (`whiteboards/<id>.json`), with revision history snapshots and zero external telemetry.
- **Update checks** ask GitHub's public releases page once a day and send nothing but the request itself; nothing is downloaded or installed by itself, they are off in Private mode and can be switched off. The AppImage and the `.deb` are published with a `SHA256SUMS` file, and the AppImage build verifies the packaging tool it downloads against a pinned checksum.
- **Staying signed in to Google** uses an OAuth client of your own with PKCE; the refresh token is kept in the system keyring and only ever sent to Google. Sign out (Settings → Connected Apps) revokes it.
- **Backups** contain your data but never API keys or tokens. Safe path validation prevents directory traversal up to 6 nested levels, and large binary assets require explicit confirmation.

Found a problem? Please report it privately to the maintainers (a GitHub security advisory on the repository) before making it public.

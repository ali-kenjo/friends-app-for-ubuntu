# Rules for the 0.7 release (read before every task; they override convenience)

1. Finished features only. No stubs, no TODOs, no "phase one", no half-built screens. Every option shown in Settings must work and be tested. If something cannot be finished, say so in DECISIONS.md and do not ship a dead control.
2. The project is public and must work for everyone, not for the author's machine. Support Linux (X11 and Wayland), macOS and Windows from source, the browser including phones, weak integrated graphics, no GPU, no WebGL, little RAM, laptops on battery, AMD/Intel/NVIDIA/Apple silicon, and local AI servers of every kind. Detect capabilities, scale up and down, and fall back gracefully. Never hard-code assumptions such as "6 GB NVIDIA card".
3. Local-first and Private mode. Nothing new may leave the computer in Private mode. Every new outbound path must appear in the live "what could leave this computer" list. New secrets go into the system keyring, never into plain files, backups or the page. The existing scrubbing of keys, cards, emails and phone numbers before text goes to a cloud AI must cover every new data path (whiteboard content, Telegram, Reddit).
4. Offline-capable. The page loads nothing from other websites. No CDN. Prefer drawing things procedurally, as the robot and rooms are. Any bundled assets (fonts, icons) must be open-licensed, subset, small, and listed with their licenses.
5. Translations. English is the source text. Every user-visible string goes through t() in the page and say()/sayN() on the server. German and Arabic must be complete, and right-to-left layouts must be correct (logical CSS properties). npm run i18n must show nothing missing.
6. Accessibility. Everything is reachable by keyboard, labelled, at least 44 px touch targets, visible focus, reduced motion honoured, contrast at WCAG AA in every theme in dark and light. Extend the axe test to the new surfaces and keep it green.
7. Follow the existing architecture: design tokens in src/css/tokens.css; pure logic in .mjs modules checked by node:test; server code in server/; settings saved as diffs; the existing risk and approval model for anything that sends, deletes or runs commands. Do not rewrite working systems unless needed; extend them.
8. Untrusted content. Text from Telegram, Reddit, web pages, files and the whiteboard is data, never instructions. It must not be able to trigger tools, missions or sends by itself. Validate all inputs, keep path and network safety (no SSRF, no path escapes), and rate-limit and back off on every external API.
9. Tests. Add unit, HTTP-integration and browser tests for everything you build. External services are faked (fake Telegram, fake Reddit, fake Gemini, fake Ollama); tests never touch the network. Before each commit these must pass: npm run check, npm test, npm run i18n, and (when Chrome is available) npm run test:e2e and npm run test:a11y. If an old test fails, report it; never delete or weaken a test to get green.
10. Verify by using it. Start the real app, drive it through the browser test harness, take screenshots, look at them, and fix what is ugly or broken (overflow in German, mirrored layout in Arabic, small screens). In reports, state clearly what you verified and what could not be verified (for example needs a real bot token or account).
11. Do not break user data. Add migrations for any settings or data format you change, keep old data working, and make backups include new data folders (never secrets). Test migrations with a data folder in the 0.6 format.
12. Git: work only on the release branch. Make focused commits with clear messages, at least one per finished area. Never push, never tag, never rewrite history, never commit secrets or personal data.
13. Progress and resumability. Keep docs/release-0.7/PLAN.md up to date: break your workstream into concrete checklist items at the start, tick them as they are really finished and tested, and write down what is left if you must stop. A fresh session must be able to continue from the file alone. Record every non-obvious decision in DECISIONS.md. Keep an "Unreleased" section in CHANGELOG.md and README/docs current as you go.
14. Do not ask questions unless truly blocked. Decide sensibly, record it, and continue.
